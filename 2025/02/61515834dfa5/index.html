Virtio/vDPA 虚拟化架构演进与 DPU 卸载技术分析

一、虚拟化架构演进流程

虚拟化 I/O 架构的演进本质上是数据面不断从"通用软件路径"向"专用硬件路径"下沉、而控制面不断标准化的过程。整个演进可以划分为六个阶段。

阶段 0：QEMU 纯软件仿真（virtio 诞生）

  • 组件：KVM（内核 hypervisor，提供 vCPU/内存管理）+ QEMU（用户态设备仿真进程）+ libvirt（XML→QEMU CLI 的管理层）。
  • 原理：QEMU 按 virtio spec 仿真一个 PCI 设备呈现给 guest；guest 内的 virtio-net 驱动通过 PCI BAR 发现设备、完成 feature 协商、分配 virtqueue。
  • 数据路径：guest 驱动写 buffer → avail ring + doorbell → KVM vmexit → QEMU 被唤醒（用户态上下文切换）→ QEMU 处理 ring → 经 tap 设备送入 host 内核协议栈/OVS。
  • 性能瓶颈（来自 Deep dive into virtio-networking and vhost-net）：
    1. 每个包至少一次 vmexit + 一次 QEMU 进程上下文切换；
    2. 每包一次 syscall + tap 读写数据拷贝，无批处理；
    3. vCPU 注入中断需要 ioctl，再次陷入内核。
  • 价值：确立了 virtio 标准接口（设备状态字段、feature bits、通知、virtqueue 四要素），这是后续一切演进的控制面基线。

阶段 1：vhost-net —— 数据面卸载到 host 内核

  • vhost 协议：定义 QEMU（master）与 handler 之间的消息集，master 把 guest 内存布局、virtqueue 地址、virtio feature 子集以及一对通知 fd（ioeventfd/irqfd）移交给 handler；此后 QEMU 完全退出数据路径。
  • 实现：vhost-net 内核驱动（/dev/vhost-net），创建 vhost worker 内核线程直接消费 virtqueue。
  • 通知旁路：
    • ioeventfd：guest 对特定 guest 物理地址的写被 KVM 直接路由到 vhost worker，无需唤醒 QEMU，且异步、不打断 vCPU；
    • irqfd：vhost 直接向 KVM 写 eventfd 即可注入 vCPU 中断，无需 ioctl。
  • 数据路径：guest ⇄ 共享内存中的 virtqueue ⇄ vhost-net 内核线程 ⇄ tap ⇄ OVS 内核 datapath ⇄ 物理网卡。
  • 收益：消除 QEMU 上下文切换与逐包 syscall；guest 完全无感知（仍是标准 virtio 前端）。
  • 遗留问题：数据仍在 host 内核协议栈中转发，中断驱动 + 内核调度开销限制了大包速率场景。

阶段 2：vhost-user + virtio-pmd —— 数据面下沉到用户态 DPDK

  • DPDK 特性：run-to-completion 模型、PMD 轮询（无中断）、CPU 亲和、hugepage、无锁 ring、VFIO 用户态驱动。
  • vhost-user：vhost 协议的 unix socket 版本。QEMU 作为 master 通过 socket 向 DPDK 应用（如 OVS-DPDK）传递内存 region（mmap 共享）、vring 配置、多队列配置和 kick/call fd。
  • 前端升级：guest 内核 virtio-net 可换为 guest 用户态 virtio-pmd（配合 VFIO + vIOMMU），guest 应用直接链接 DPDK 库。
  • 地址翻译链（IOMMU 使能时）：guest IOVA →(vIOMMU)→ GPA →(QEMU 内存管理)→ QEMU HVA →(mmap 偏移)→ vhost-user 进程 HVA；IOTLB miss 经二级 unix socket 向 QEMU 查询，DPDK 静态 hugepage 分配使 IOTLB 同步消息降到最低。
  • 收益：主机与虚机两侧都绕开内核，性能较 vhost-net 提升 2–4 倍（OVS-DPDK 约 10 倍于原生 OVS）。
  • 代价：易用性下降——guest 应用必须改造为 DPDK 应用；专用核心轮询耗 CPU。

阶段 3：SR-IOV 直通 —— 硬件线速但厂商锁定

  • 机制：PCIe 单根虚拟化。PF 管理整机，切出多个 VF；每个 VF 拥有独立 Requester ID，IOMMU 据此做 DMA 隔离，VF 可直接分配给 guest。
  • 数据面：VF 与 guest 之间以厂商私有 ring 格式直接 DMA 通信，达到线速。
  • 缺陷（introducing vDPA 一文的批判点）：
    1. guest 必须运行厂商专用驱动（内核 VF 驱动或 DPDK PMD），驱动版本与网卡固件强耦合；
    2. 换网卡厂商 = 换 guest 驱动 = VM 需重新认证；
    3. 热迁移只能在同型同版网卡间进行；
    4. ring 格式私有，无生态标准。

阶段 4：virtio full HW offloading —— 全硬件标准接口

  • NIC 内的 VF 直接同时实现 virtio 数据面 + virtio 控制面（PCI 配置空间、feature 协商、状态机全部在硬件中）。
  • guest 用标准 virtio-net 驱动或 virtio-pmd 直接驱动硬件，host 侧仅需 VFIO 通用框架。
  • 缺陷：要求厂商在 NIC 内完整实现 virtio 控制面（通常为软件职责），工程量大；spec（1.1）未覆盖脏页跟踪等迁移能力，需 QEMU 与 NIC 之间的私有 API 扩展。

阶段 5：vDPA —— "标准数据面 + 适配控制面"的终局形态

  • 定义（virtio data path acceleration）：数据面遵循 virtio ring 标准，控制面保持厂商私有，由 host 侧 vDPA 适配层翻译为标准 virtio 控制面。
  • 两条实现路径：
    1. 内核路径：MDEV 框架（vfio-mdev/virtio-mdev transport API）+ vhost-mdev（桥接用户态 vhost 命令）+ vhost-vfio（QEMU 侧用户态驱动，负责 vIOMMU 映射经 VFIO container 下发）。
    2. DPDK 路径：rte_vdpa_dev_ops 回调集（get_features/set_features/dev_conf/get_notify_area 等）桥接 vhost-user 协议与厂商 vDPA 驱动；还有通用 virtio-vDPA 驱动可直接驱动 full HW offload 设备。
  • 八大优势（原文归纳）：开放规范、线速、面向 S-IOV 等新硬件、VM 单次认证、后端透明保护（backend-protection，断链自动切回 vhost-net）、跨厂商热迁移、容器标准加速接口（AF_VIRTIO 愿景）、裸机通用 virtio 驱动愿景。

二、基于 DPU 的虚拟化卸载：控制面协商与数据面转发技术分析

DPU（含 BlueField、Pensando 等 SmartNIC/IPU）上的 virtio 卸载，技术上等价于"vDPA 架构的工程化落地"：DPU 的 ARM 核运行控制面软件（vendor 驱动/管理面），DPU 的可编程数据面（ASIC/NFP/嵌入式转发核）实现 virtio ring 的硬件消费。以下按控制面、数据面分述。

2.1 控制面协商技术

(1) virtio 标准初始化序列（所有架构共通，guest 侧唯一契约）

feature bits 分两层：设备无关（如 VIRTIO_F_EVENT_IDX、RING_PACKED、IOMMU 平台特性）与设备相关（virtio-net 的 offload：checksum、TSO/GSO、mergeable buffer、MQ 多队列等）。DPU 必须以硬件实际能力如实协商，否则 guest 标准驱动的行为不可预期。

(2) vDPA 三种控制面实现路径（host 侧适配层）

路径 承载协议 核心组件 说明
内核 vDPA ioctl（vhost_net 兼容命令） vhost-mdev（用户态命令→virtio-mdev transport API）+ vhost-vfio（QEMU 侧，处理 vIOMMU 映射） virtio-mdev transport API 抽象了 set/get config、set vring addr/size/base、kick vq、注册 IRQ 回调、feature 协商、set/get dirty log、start/reset 八类原语，厂商仅需实现该 API
DPDK vDPA vhost-user unix socket rte_vdpa_dev_ops 回调（get_queue_num/get_features/get_protocol_features/dev_conf/set_vring_state/set_features/migration_done/get_vfio_group_fd/get_vfio_device_fd/get_notify_area） dev_conf 回调一次性完成 ring 地址、DMA 映射、设备启动；面向容器/裸 DPDK 前端
full HW offload PCI 直通 DPU 固件直接实现 virtio 控制面 + VFIO 设备透传 控制面无需 host 软件，但脏页跟踪等需 QEMU↔︎NIC 私有扩展

(3) DMA 域建立（vDPA 控制面最关键、最易出错的环节）

数据面直达的前提是 DPU 硬件能对 guest 内存做 DMA，完整的映射链为：

  • vhost-vfio 收到 QEMU vIOMMU 的 map/unmap 请求后经 VFIO container fd 下发，保证 mdev 设备拿到正确映射；
  • DPDK 前端采用静态 hugepage 映射，使 IOTLB miss 与设备 TLB 同步消息（ATS 翻译请求走二级 socket）降至最低——这是性能工程的关键实践；
  • 每个 VF/mdev instance 有独立 IOMMU group（Requester ID 隔离），实现 DMA 攻击防护。

(4) 通知通道注册

  • get_notify_area 回调 / virtio-mdev kick 原语：把 DPU 硬件 doorbell 的 MMIO 区域（offset+size）暴露给前端，使 guest 的 kick 写直达硬件寄存器（经 ioeventfd 或 BAR 映射），跳过任何软件中转；
  • IRQ 注册：DPU 的中断经 irqfd 或 vIRQ（直通场景）注入 guest；VIRTIO_F_EVENT_IDX 协商后，事件抑制按 descriptor 序号精确触发，供批量转发摊薄通知成本。

(2) 各代架构数据面路径对比

架构 软件路径 DMA/内存 通知 性能量级
QEMU 仿真 guest→KVM→QEMU→tap→内核栈 QEMU 用户态拷贝 vmexit+ioctl 中断 慢

(3) DPU 数据面工程要点

  1. Ring 布局选择：现代 DPU 一般实现 packed virtqueue（单连续区域利于 ASIC 访问、减少 PCIe 事务），同时兼容 split 以支持旧 guest；DPU 硬件消费 ring 时需精确实现 wrap counter 语义与 out-of-order 完成判定（AVAIL/USED 与内部 wrap 计数的六种组合）。
  2. 描述符批处理：一次 doorbell 消费多个描述符；回写 used 时仅写链尾 id（packed）以减少共享内存写带来的 cache bounce。
  3. 通知抑制的硬件化：VIRTIO_F_EVENT_IDX 的 avail_event/used_event 比较逻辑在 DPU 转发核中实现，配合中断聚合，是"通知开销→0"的关键；轮询模式（busy polling）适合核心数充足的 NFV 场景。
  4. Offload 协同：virtio-net feature 协商的校验和卸载、TSO/GSO、mergeable buffer 由 DPU 硬件执行，guest CPU 卸载收益与 SR-IOV 等价。
  5. QoS/多租户：DPU 在转发核内按 VF/queue 做 rate limiting 与流分类，控制面经 PF 管理接口（vendor 路径）配置——这正是控制面"厂商私有"仍保留价值之处。
  6. 热迁移支持：迁移期间 vDPA 框架可切换为软件处理 ring（vhost-net/vhost-user 后端）以执行脏页跟踪，完成后切回硬件——backend-protection 机制同时覆盖 DPU 故障降级。

2.3 总结

  • 演进规律：控制面从"每代重写"收敛为 virtio spec 单一契约；数据面从"trap-and-emulate"演进为"shared-memory ring + 硬件 DMA 直达"。DPU 是 vDPA 架构的自然载体：其 ARM 核承载厂商私有控制面与 vdpa 适配层，其转发核承载 virtio ring 硬件消费。
  • 设计精髓：把"必须标准化的部分"（guest 可见接口、ring 格式、feature 协商）固化进 virtio 1.1 spec，把"允许差异化"的部分（内部转发流水线、流表、管理面）留给厂商——guest 只需一次认证、可跨厂商热迁移，DPU 厂商只需在 host 侧实现薄适配层。
  • 未竟之路（系列博客的展望，也是当下现状）：Scalable IOV/ADI 粒度的资源切分、容器场景的 AF_VIRTIO/socket 化加速接口、virtio 作为裸机通用网卡驱动。
